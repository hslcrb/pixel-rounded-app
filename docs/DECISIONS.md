# Architecture Decision Records (ADR)

## ADR-001 — Electron + Vanilla JS

- 결정: Electron 45, Canvas 2D, 브라우저 기본 JS/CSS/HTML.
- 배경: 사진 연구 도구를 로컬 우선·이해 쉬운 코드·작은 런타임 종속성으로 만들기 위함.
- 대가: Electron 바이너리 크기 자체는 작지 않으며 큰 사진에서 UI 스레드 부하가 존재함.
- 대안: Tauri/WASM, WebGL, React + Electron. 이후 고성능 버전에서 재검토.

## ADR-002 — 비파괴 원본 보존

- 결정: 원본 프리뷰는 불변, 엔진은 새 Uint8ClampedArray 반환. 저장 시 원본 해상도로 재처리.
- 이점: Undo/Redo는 조절 값만 기록; 오염된 원본에 필터를 누적하지 않음.
- 대가: RAM 사용량 증가, 저장 시간 증가.

## ADR-003 — Source-available PR-SAL-1.0

- 결정: 자체 재배포·상업화 제한 조건과 공식 프로젝트 기여 허용.
- 이점: 저작권과 브랜드 통제를 원하는 목적에 부합.
- 대가: **OSI 오픈소스가 아니며**, 자유로운 downstream 포크·패키징이 제한됨. 권리 보호를 완벽하게 보장하지 못함.
- 추후: 법률 검토 및 별도 커뮤니티 라이선스 가능성 평가.

## ADR-004 — 전후 픽셀 페어 최적화

- 결정: 원본/참조 사진의 픽셀 RGB MSE를 최소화하는 결정론적 전역 파라미터 탐색.
- 이점: 로컬에서 학습 서버 없이 작동, 오차와 추정 과정을 문서화 가능.
- 한계: 같은 장면에 대해 색감만 대략 근사, 구도/마스크/특정 질감을 완벽히 복원하지 못함.
- 미래: 자동 정렬, 선형 색공간, 국소 색 보정, LUT.

## ADR-005 — 직접 제작 오프라인 이미지

- 결정: 앱에는 직접 만든 풍경 SVG를 예시로 넣고 실사진은 라이선스 확인된 외부 CC0 링크를 테스트 가이드에 제공.
- 이점: 네트워크 없는 실행과 타인의 권리 침해 위험 감소.
- 한계: 원본 JPEG/WebP 등 실제 포맷 테스트는 따로 수행해야 함.
