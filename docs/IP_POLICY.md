# IP & Attribution Policy

> 원본 사진, 기여자의 코드, 브랜딩, 프로젝트 소스의 권리를 구분하기 위한 운영 정책입니다.

## 권리의 네 층위

1. **프로젝트 원본 소스/디자인:** hslcrb의 pixel-rounded 원본 코드, 직접 제작한 로고와 그래픽 등은 `LICENSE`의 범위에서 공개됩니다. 자신에게 권리가 없는 자산에 동일 라이선스를 임의로 부여하지 않습니다.
2. **기여자 코드와 문서:** 기여자는 원본 저작권을 보유합니다. PR 제출 시 저장소 LICENSE의 비독점 사용 허락 조항을 적용합니다. 별도의 저작권 양도는 발생하지 않습니다.
3. **타사 라이브러리/폰트/사진:** 각 권리자의 원래 라이선스를 준수해야 합니다. 예를 들어 Electron의 MIT 권리를 pixel-rounded 독자 라이선스로 축소할 수 없습니다.
4. **사용자가 편집한 사진:** 편집했다는 이유로 소프트웨어가 사진의 저작권이나 독점 사용권을 취득하지 않습니다. 원본 촬영자나 피사체 초상권 등의 의무는 사용자에게 남습니다.

## 금지 사례와 정상 사례

- ❌ 저장소의 코드를 가져가 독립 유료 제품을 만들어 본 제품인 것처럼 광고
- ❌ 타인의 상업용 사진과 폰트를 무단으로 저장소에 포함
- ❌ 타인의 PR 기여 저작권을 자신의 단독 작품으로 표시
- ✅ 합법적인 개인 촬영 사진으로 필터 실험
- ✅ 라이선스가 허용하는 공개 사진을 출처를 확인하고 테스트
- ✅ 공식 프로젝트 기여를 위해 GitHub에서 제한적으로 Fork/PR 제출

권리자라면 공식 GitHub 저장소에 충분한 증빙(권리자와 소재의 출처, 문제 파일, 원하는 조치)을 첨부하여 문의해 주세요. 민감한 개인정보가 포함된다면 공개 이슈 대신 비공개 연락 경로를 먼저 문의하세요. 합리적으로 검토하고 필요한 자료 제거·수정·적절한 고지를 진행하는 정책을 권장합니다.
